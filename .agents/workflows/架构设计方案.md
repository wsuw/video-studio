# VideoAgent 架构设计方案 (v1.1)

本文档记录了 VideoAgent 的核心路由、状态管理及数据持久化方案，旨在确保 AI 与用户在视频创作过程中的深度协同。

## 1. 路由设计 (Routing Strategy)

采用基于项目 ID 的动态路由结构，确保多项目并行开发的隔离性与链接稳定性。

- **核心路径**: `/workspace/[projectId]/[stage]/[sub-page]`
- **阶段划分与子页面**:
    - **Design 创意蓝图阶段**: `/design/script` (剧本), `/design/breakdown` (声线与角色绑定), `/design/style` (风格设定), `/design/storyboard` (分镜设计), `/design/voiceover` (配音合成及情绪微调)
    - **Generation 资产生产阶段**: `/generation/keyframes` (关键帧生成), `/generation/video` (视频生成)
    - *重构说明*：`Voiceover` 已重新调整至创意设计（Design）阶段（Storyboard 之后），作为高确定性的预生产规格。这使得配音时长能够无缝锁定后续 LTX-2 关键帧和视频生成的渲染时值。
- **设计理由**: 
    - **隔离性**: 不同项目拥有独立的 URL 空间。
    - **持久化**: 刷新页面或分享链接可直接进入对应项目的特定创作阶段。
    - **安全性**: 顶级路由（如 `/workspace`）作为应用入口，便于中间件进行统一鉴权。

## 2. 状态管理与同步 (State Management)

AI 助手与 UI 界面共享同一个“大脑状态”，实现真正的协同创作。

- **单一事实来源 (Single Source of Truth)**: 采用 **LangGraph State** 存储创作过程中的核心数据（如脚本、分镜约束等）。
- **实时同步**: 通过 **CopilotKit** 将前端 UI 状态与后端 Graph 状态绑定。
- **AI 感知**: AI 通过 `useCopilotReadable` 实时观测用户输入，通过 `useFrontendTool` 直接修改 Graph 状态并驱动 UI 更新。

## 3. 数据持久化方案 (Data Persistence)

解决 AI 应用中“状态即数据”的存储难题。

- **Checkpointer 机制**: 使用 LangGraph 的 `AsyncPostgresSaver` 作为底座。
- **存储逻辑**: 
    - **Thread ID 映射**: 直接将 `projectId` 作为 `thread_id`（建议格式为 `f"project:{projectId}"`）。
    - **主动保存 (Proactive Save)**: 前端“保存”按钮不再直接操作业务数据库，而是通过 API 调用 `graph.update_state`。这会强制 Checkpointer 写入当前状态快照。
    - **版本回溯**: 利用 Checkpointer 的历史记录功能，原生支持脚本的 Undo/Redo 和版本对比。

## 4. 后续演进

- **结构化导出**: 脚本在“设计”阶段完成后，由 Agent 自动将其从 Graph State 提取并存入结构化的业务数据库表，供后续“生成”阶段作为静态输入。
- **分阶段 Thread**: 如果项目极其复杂，可考虑采用 `projectId:stage` 的格式进行 Thread 隔离。
- **离线高性能生成集群集成 (LTX-2 Routing)**：在“生成”阶段，引入本地部署的高性能 LTX-2 19B 微服务（运行于本地 8125 端口）。前端与 LangGraph 编排层通过发送携带 `stage1_only: bool` 的 `/generate` API 请求，实现动态的双通道任务分发。在低算力开销/快速确认模式下执行 Stage 1 极速草稿渲染（~110秒），在终稿确认阶段执行 2-Stage 高清成片渲染，使状态机在算力资源和交互效率上具备自适应能力。

## 5. 声音与视频时值协同渲染 (Voiceover-Video Temporal Constraint)

- **时值物理依赖**: 在 Generation 阶段，系统先通过本地离线语音合成服务（运行于 8000 端口）获取精准的角色配音音频文件。
- **动态帧数锁定机制 (Frame Rate Lock)**: 
    - 视频生成（Video Gen）模块订阅当前场景状态中的 `audio_duration`。
    - 若 `audio_duration > 0`，前端界面会自动锁定“目标生成帧数（Target Frame Count）”滑块，其计算公式为：
      $$\text{Locked Frames} = \text{round}(\text{audio\_duration} \times \text{frameRate})$$
    - 该设计在架构层面强制保证了**画面动作长度与声音物理时长 100% 对齐**，彻底规避了音画不同步的工业级痛点。

🎬 VideoAgent 北极星架构指南 (North Star Architecture Guide)
版本： 2.0 (Ultimate Industrial Edition)
核心宗旨： 全自主是“玩具”，受控流水线才是“工具”
。
设计初衷： 在算力昂贵、模型存在随机性的当下，通过工业化流程实现 “低成本纠错” 与 “高确定性产出”
。

--------------------------------------------------------------------------------
🏛️ 第一部分：核心哲学 (Core Philosophies)
1. 导演-助理模式 (Director-Agent Synergy)
AI 定位：系统中 Agent 不是独立的创作主体，而是**“高级助理 (Expert Staff)”**
。它负责执行繁琐的计算（Bounding Box 坐标）、逻辑扩写（Logline 演进）和工具调用。
人类定位：用户是唯一的**“导演 (Director)”**
。人类不参与重复体力活，但在每一个核�🔄 第二部分：电影工业管线与 Agent 节点映射 (六大阶段)
基于现代电影工业的标准生命周期，VideoAgent 的核心管线扩展为更具确定性的 6 步制管线。
。
阶段一：前期开发 (Development Node) —— 剧本的工业化演进
哲学要义： 文本是电影的灵魂，拒绝从一句话直接跳跃到画面
。
分级演进 (Gradual Evolution)：引入 Deep Agents 模拟“编剧部”，强制约束 AI 遵循电影工业标准进行层层递进：
Logline (核心悬念) → Synopsis (梗概) → Treatment (纲要) → First Draft (初稿) → Locked Script (锁定脚本)
。
剧本锁定：剧本一旦经由导演（用户）审核并“锁定”，即作为后续所有部门的法定执行依据，系统不可再随意更改核心叙事
。
阶段二：前期筹备 (Pre-Production Node) —— 分子级拆解与全局建档
哲学要义： 在画出第一张草图前，必须先确立资产档案与物理骨架
。
分子级拆解 (Script Breakdown)：AI 自动对锁定剧本进行解剖，提取出所有的视觉实体要素，包括角色 ID、核心服装、特殊道具和场景表
。
全局上下文建档 (GCM - Global Context Manager)：为拆解出的核心角色建立“主视觉档案 (Master Portrait)”。这确保了后续跨镜头生成时，AI 能够强制检索并保持角色身份和容貌的绝对一致性，杜绝“千人千面”
。
空间规划与防线 (Spatial Planning & HITL)：利用 LayoutGPT 等视觉规划模型提前计算每一帧物体的边界框坐标 (Bounding Box)
。此时触发 LangGraph 的 interrupt() 原语拦截，在下发昂贵渲染指令前，向导演展示带有 Bbox 轨迹 Caucasian 画板，确认无误后才放行
。

阶段三：演员配音 (Dubbing Node) —— 时序锚定与口型驱动的前置依赖
哲学要义： 声音是时空张力的起点，决定画面的物理边界与动作表情
。
时序锚定 (Temporal Anchoring)：通过 TTS 语音模型提前为分镜台词生成音频，获取高精度时长参数（秒数），动态指导后续视频生成帧数（例如配音时长 4.8 秒，以 24fps 换算，视频需生成 115 帧），彻底杜绝音画不同步。
口型与表情驱动准备 (Lip-Sync Prep)：生成克隆和角色台词音频，为后续视频生成中的口型动作驱动大模型（如 Wav2Lip, LivePortrait 等）提供高确定性的音频流依赖。
导演声线试听审批 (HITL Voice Casting)：支持角色多声线试听与语速语调微调，当导演（用户）试听满意并“锁定”音频后，方可启动高成本的画面摄制。
。

阶段四：正式摄制 (Generation Node) —— 算力黑盒与指令转化
哲学要义： 将导演的创意意图，精准“翻译”为渲染引擎参数。

双流渲染机制 (Dual-Stream Rendering)：为了将高昂的渲染算力成本降至最低，引入“草稿/终成片”分级通道：
1. **草稿预演流 (Draft Preview - Stage 1 Only)**：输出类型设为 numpy，仅进行 8 步基础步数生成，直接通过 VAE 解码为像素级帧（运行耗时 ~110 秒，每步 ~6.2 秒）。用于提供低成本、高效率的时空动感和构图草卷，供“导演”迅速进行第一级决策。
2. **完整精炼流 (Final Refinement - 2-Stage Pipeline)**：基于已验证的 Stage 1 隐空间数据，通过 Latent Upsampler 放大，再配合专用 Stage 2 蒸馏 Sigmas 运行 3 步精炼，最终由 VAE 铺砖渲染输出高清终稿。

指令下发 (Instruction Dispatch)：利用 MCP (模型上下文协议)，将预演好的时空参数和镜头语言安全地隔离地下发给底层的 ComfyUI 或其他大模型渲染集群（如运行在 8125 端口的本地离线 LTX-2 渲染微服务）。

持久化休眠 (Durable Execution)：渲染是重体力活。面对长耗时任务，LangGraph 必须执行 Checkpointing (检查点存档) 并进入休眠，释放内存资源。系统通过 Webhook 回调唤醒，确保长耗时任务不会中断崩溃。

阶段五：后期质检 (Redesign Node) —— 针对“漂移”的多专家防线
哲学要义： 放弃“单次生成即完美”的幻想，建立自路由反馈回路
。
VLM 质检员 (Verification Agent)：利用视觉大模型严格对比“锁定脚本”与“生成素材”，检查对象存在性、数量、动作逻辑与空间关系
。
自路由纠错 (Self-routing Correction)：采用 GENMAC 协作机制，根据报错类型自动唤醒特定专家：
一致性问题 → 路由至 一致性专家 修复角色脸部或服装漂移
。
时空动态问题 → 路由至 时空动态专家 修改 Bbox 坐标或运动幅度
。
原子化局部重绘：严禁无脑重跑整个长镜头，必须结合智能体的建议 (Suggestion) 与结构化输出 (Output Structuring)，实现仅针对错误帧的精准局部重绘
。

阶段六：合成与衍生 (Distribution Node) —— 工业级成片与分发
哲学要义： 碎片化素材的无缝缝合与全渠道价值放大
。
自动化多轨合成：通过 MCP 封装的 FFmpeg 服务器，由 Agent 自动完成视频轨、旁白配音 (TTS)、环境音 (SFX) 与时间戳字幕的精准混音与对齐
。
多平台适配：利用自动化脚本提取“视觉锚点”，将 16:9 横屏素材智能剪裁为适合短视频平台的 9:16 竖屏，并自动提取具有传播潜力的 Hooks (钩子) 制作高光预告片
。��并保持角色身份和容貌的绝对一致性，杜绝“千人千面”

🛠️ 第三部分：技术红线 (Technical Constraints)
禁止黑盒直出： 严禁让模型在没有任何中间状态（如 JSON 大纲、角色档案、Bbox 坐标）的情况下直接吞入剧本文本生成长视频
。
强制 MCP 隔离： 所有的底层 Tool 调用（本地文件系统、ComfyUI 操控、FFmpeg 合成）必须通过标准化的 MCP 进行，以保证执行层与推理层完全解耦和环境安全
。
强制 HITL 拦截： 在核心的“拆解建档”阶段与“重构纠错”阶段，必须配置 Human-in-the-Loop (人在回路) 审批网关。这是系统脱离“玩具”标签、迈向“工业生产力工具”的绝对物理前提
。
强制状态持久化： 全局状态对象（State）必须通过数据库持久化（如 PostgresSaver），并确保跨智能体协作中的上下文纯净与内存安全。
强制 Pipeline Hook 纯净性与显存保护：在本地 24GB GPU（如 RTX 3090/4090）物理运行 LTX-2 19B 极大型模型时，必须确保文本编码器（Gemma 3）和隐空间扩散网络（LTX-2 Transformer）由 Diffusers 自动 CPU 卸载 Hook 进行精准的依序加载与释放。严禁在代码中插入任何手动的模型权重移动（`.to("cpu")`）或预先手动 Prompt 编码，这会破坏自动引用计数引用并破坏 Hook 触发条件，诱发 VRAM 溢出至系统物理内存并触发 Windows WDDM Paging 引起致命降速。
